## 0. 背景摘要

TENET「信条」官网（xin-tiao.top）V1 的目标：建立一个「品牌展示 + 用户引导 + 转化闭环」的完整首页，并搭好可持续迭代的官网骨架。
关键约束：单人开发、AI 辅助、低成本长期迭代、必须实际上线；首页内容不得写死；支持中英双语与 PC/移动端。

## 1. Product Goal

1. 让首次访问用户在 30 秒内理解：TENET 是什么、能做什么、如何开始使用。
2. 完成「理解 → 信任 → 行动」的引导路径，核心行动点 = 进入模型广场 / 登录使用。
3. 首页品牌展示内容可配置（不写死在代码里），后期可自行修改。
4. 为后续版本（导航动效、社区、文档体系、对接控制台）预留扩展结构。

## 2. User Problem

- 目前 xin-tiao.top 直接暴露 new-api 控制台，缺少品牌化的官方介绍入口，用户无法理解产品价值。
- 用户想了解「有哪些模型、什么价格、怎么开始」时没有清晰的引导路径。
- 没有「官网品牌展示 → 登录转化」的产品闭环。

## 3. Target User

- 开发者 / 技术用户：需要多模型 API 调用、聚合中转服务。
- 个人创业者 / 中小团队：需要稳定、隐私、低成本的 AI 服务。
- 语言：默认中文（zh），提供英文（en）切换。
- 终端：PC 浏览器 + 移动端浏览器双端覆盖。

## 4. User Journey

**新用户（首次访问）**
1. 进入首页 → 看到品牌展示（Hero）与价值主张
2. 向下浏览 → 理解「服务用户 / 保护隐私 / 平台稳定」
3. 看到「如何开始」3 步引导：注册 → 创建密钥 → 调用 API
4. 浏览模型广场预览 → 点击进入模型广场看模型与价格
5. 点击「登录 / 注册」→ 跳转控制台完成注册
6. 回官网/文档查阅使用说明

**老用户（再次访问）**
1. 进入首页 → 直接点导航「模型广场 / 文档 / 登录」

## 5. Information Architecture

```
xin-tiao.top（官网）
├── 首页 /
│   ├── Dynamic Island 导航栏（固定）
│   ├── Hero 品牌展示（内容驱动，可改）
│   ├── 价值理念区（三卡片）
│   ├── 模型广场预览（精选模型卡片）
│   ├── 如何开始（3 步引导）
│   ├── 定价速览（入口 → 模型广场）
│   ├── 底部 CTA
│   └── Footer（品牌/导航/协议/语言）
├── 模型广场 /plaza（定价 + 模型 合并）
├── 关于 /about
├── 文档 /docs
├── 社区 /community
└── 登录入口（导航 CTA，跳转控制台登录，目标地址待确认）
```

导航栏项（固定）：
`[Logo=首页] | 模型广场 | 关于 | 文档 | 社区 | [登录] [语言切换]`

## 6. Page Structure（首页自上而下）

### 6.1 Dynamic Island 导航栏
- 桌面：页面顶部**固定**，居中悬浮胶囊（类似灵动岛）
  - 视觉：大圆角胶囊、毛玻璃（backdrop-blur）、细边框、微弱阴影、内边距
  - 内容：Logo + 品牌名（左）｜模型广场/关于/文档/社区（中）｜登录 + 语言（右）
- 移动端：紧凑胶囊，Logo + 汉堡菜单（抽屉展开）+ 登录按钮
- V1 只做固定定位；展开/收起、滚动态、交互动效 **V2 再做**

### 6.2 Hero 品牌展示区（内容驱动）
- 内容由内容文件（JSON/Markdown）驱动，**不写死在代码中**：主标题、副标题、一句话理念、主 CTA 文案/链接、次 CTA 文案/链接、背景配置
- 主 CTA：进入模型广场（橙色实心）
- 次 CTA：立即开始 / 查看文档
- 背景：Neural Flow 轻量节点连线动效（克制，尊重 `prefers-reduced-motion`）

### 6.3 价值理念区
- 三张卡片：服务用户 / 保护隐私 / 平台稳定
- 每卡：图标 + 标题 + 一句话说明（内容文件驱动）

### 6.4 模型广场预览
- 精选 3~6 个模型卡片：模型名、简介、价格/符号、标签
- 点击「查看全部模型」→ 进入模型广场
- 数据来源：V1 用内容文件（JSON），后期可选对接 new-api 公开接口（待确认）

### 6.5 如何开始（3 步引导）
- 步骤 1 注册账号 → 步骤 2 创建 API 密钥 → 步骤 3 调用模型
- 每步可带链接（登录 / 文档）
- 目的：给新用户明确的使用路径

### 6.6 定价速览
- 简要说明价格模式（按量计费等，文案待确认）+ 入口按钮 → 模型广场

### 6.7 底部 CTA
- 大标题式行动号召：「开始使用 TENET」+ 登录/进入模型广场按钮

### 6.8 Footer
- 品牌 Logo + 一句话理念
- 导航链接、协议链接（用户协议/隐私政策）、备案信息（待确认）
- 语言切换、版权行

## 7. Functional Requirements

| # | 需求 | 说明 |
|---|------|------|
| F1 | 导航栏固定 | Dynamic Island 样式，固定顶部，不随滚动消失 |
| F2 | 首页内容可配置 | Hero/理念/模型预览/引导区内容来自内容文件，修改内容文件即可改首页，不涉及代码 |
| F3 | 模型广场 | 模型 + 价格合并页，V1 由内容文件驱动；预留对接 new-api API 的能力 |
| F4 | 中英双语 | zh 默认，可切换 en；切换状态可记忆（localStorage） |
| F5 | 响应式 | PC / 平板 / 移动端布局适配 |
| F6 | 登录入口 | 导航登录按钮跳转控制台登录页（目标地址待确认） |
| F7 | 引导 CTA | 首页多处 CTA 指向 模型广场 / 登录 / 文档 |
| F8 | 轻量动效 | 仅 Hero Neural Flow + 基础 Hover/过渡，克制 |

## 8. UI Requirements

- 设计语言：Intelligent Minimalism（见设计宪章）
- 色彩：白 / 浅灰 / 深灰 / TENET 橙（橙色仅 CTA、Hover、Highlight、状态点睛）
  - TENET 橙参考 Claude 官方橙色，候选色值约 `#D97757`（待确认精确值）
- 导航栏：悬浮胶囊 + 毛玻璃 + 细边框 + 大圆角（如 999px），暗色模式兼容待确认
- 卡片：圆角、细边框/浅阴影、Hover 上浮
- 字体：中英文系统字体栈优先，具体字体系统待确认
- 间距/栅格：统一设计 tokens，具体值待确认

## 9. Interaction Requirements

- V1 导航栏仅固定，无复杂动效（动效 V2）
- Hover：链接/按钮/卡片反馈（上浮、颜色过渡）
- 移动端：汉堡菜单展开/收起抽屉
- 语言切换：即时切换并持久化
- 滚动：可选轻量「渐进出现」（IntersectionObserver，尊重 reduced-motion）
- 所有动画必须克制、服务信息表达

## 10. Responsive Requirements

- 断点（建议，待确认）：移动 <768px；平板 768–1024px；桌面 >1024px
- 移动端：单列布局、汉堡导航、CTA 触控高度 ≥44px、图片自适应
- 桌面端：居中内容容器（最大宽度建议 1200px，待确认）
- 不允许横向滚动、文字溢出

## 11. Technical Requirements

### 11.1 技术栈方案（见 16 章对比，推荐方案 A）
- 推荐：**Astro（静态站）+ Tailwind CSS + 内容集合（Content Collections）**
- 备选：React 19 + Rsbuild + Tailwind 静态多页（与现有控制台技术栈一致）

### 11.2 内容驱动
- 首页各区块内容存于 `src/content/`（JSON/Markdown），构建时渲染
- 修改内容 = 改内容文件 → 重新构建部署，不碰页面代码

### 11.3 国际化
- Astro 官方 i18n：`/zh` 默认，`/en` 英文（或根路径默认中文 + `/en` 前缀，待确认）
- 文案统一走 i18n key，内容文件区分语言

### 11.4 部署（需确认）
- 静态产物由 Caddy 直接伺服，服务器无需 Node 常驻进程，成本最低
- 域名规划见 17 章

## 12. Performance Requirements

- 移动端 Lighthouse Performance ≥ 90
- LCP < 2.5s；静态站默认零/极少 JS
- 图片压缩 + 现代格式（WebP/AVIF）+ 懒加载
- 字体子集化/系统字体优先
- 禁止影响性能的持续动画

## 13. SEO Requirements

- 每页：title / description / canonical / OG 标签
- 语义化 HTML（header/nav/main/section/footer，heading 层级）
- sitemap.xml + robots.txt
- 中英 hreflang 声明
- 结构化数据：Organization（可选 Product）

## 14. Acceptance Criteria

- [ ] 首页完整可浏览，无死链、无 Console error
- [ ] 导航栏固定显示，PC/移动端均正常
- [ ] 修改内容文件后重建，首页对应区块可更新（验证可配置性）
- [ ] 中英切换可用且状态持久化
- [ ] PC ≥1024px 与移动 <768px 均无布局错乱、无横向滚动
- [ ] 所有 CTA 指向正确（模型广场/登录/文档）
- [ ] 移动端 Lighthouse Performance ≥ 90，LCP < 2.5s
- [ ] 每页 SEO 基础标签齐全，sitemap/robots 可访问
- [ ] 登录按钮跳转控制台登录页成功

## 15. Out of Scope（V1 不做）

- 导航栏动效与复杂交互（V2）
- 后台管理系统 / 动态 CMS（V1 用内容文件，后续再加编辑能力）
- 支付、账户体系（复用 new-api 控制台）
- 社区功能本体（V1 仅社区入口/占位页）
- 文档内容体系（V1 仅文档入口/占位页）
- 控制台界面改造（属于 Console 二改，不属于官网）

## 16. 技术栈方案对比

### 方案 A：Astro + Tailwind（推荐）
- 优点：内容集合 + 官方 i18n + 静态输出开箱即用；SEO/性能极佳；部署零依赖；AI 辅助开发友好
- 缺点：引入新工具链（学习成本低）
- 成本：低（静态托管）
- 推荐原因：营销站天然适合静态内容站，长期内容迭代最省心

### 方案 B：React 19 + Rsbuild + Tailwind（与现有控制台一致）
- 优点：与现有技术栈一致，团队最熟
- 缺点：营销站需手动处理 i18n/SEO/预渲染多页，内容管理更费劲
- 成本：中

### 方案 C：纯静态 HTML/CSS/JS + 内容 JSON
- 优点：最轻、零构建依赖
- 缺点：多语言与可维护性差，后期扩展成本高
- 成本：最低但长期吃亏

**推荐：方案 A（Astro）**

## 17. 部署与域名方案（需确认）

现状：`xin-tiao.top` 目前经 Caddy 反代指向 new-api 容器（`127.0.0.1:3000`），暂无官网部署入口。

- **路线 1（推荐）**：官网静态站占主域名 `xin-tiao.top`；new-api 控制台迁移到子域名（如 `console.xin-tiao.top`）
  - 品牌最完整，官网作为品牌门面
  - 影响：需修改 Caddy 配置与容器路由，涉及生产，必须由项目负责人批准后操作
- **路线 2（最小改动）**：官网挂子域名（如 `www.xin-tiao.top` 或 `home.xin-tiao.top`），主域名继续指向控制台
  - 改动小，但品牌感弱，控制台仍是门面
- 待确认：选哪条路线；登录按钮跳转目标地址；是否预留备案信息位
