# 模型广场数据管理说明

> 本文档说明「模型广场」的数据来源与后续如何管理，方便非技术负责人维护。

## 当前状态（V1.1）

模型广场首页显示的是**厂商分级目录**：OpenAI / Anthropic / DeepSeek，每个厂商下列出对应模型。

数据当前存放在静态内容文件中（不是实时数据）：
- 中文：`web/src/content/home.zh.json` → `models` 部分
- 英文：`web/src/content/home.en.json` → `models` 部分

修改模型数据 = 编辑这两个 JSON 文件 → 重新 `bun run build` → 生效。

## 为什么要做「分级目录」

- 模型按厂商分组，用户点厂商卡片能看到该厂商下的具体模型
- 首页只展示「厂商一级目录」，点进去看模型细节
- 避免首页信息过载，符合 Intelligent Minimalism

## 模型数据会实时变化，怎么在后台管理？

这是**关键需求**。目前是静态文件，后期有两种升级路径：

### 方案 A（推荐，V2 做）：对接控制台 API
- New API 控制台本身有模型管理能力（模型列表、价格、启用/停用）
- 官网模型广场可以通过调用控制台的公开接口（如 `/api/models`）实时拉取模型列表与价格
- 优点：后台改模型 → 官网立即同步，无需重建
- 需要：确认控制台公开接口的认证方式（是否需 API Key）

### 方案 B（过渡）：静态内容文件
- 现在的做法，改 JSON + 重建
- 优点：零依赖、立刻可用
- 缺点：不是实时，改一次要重新构建部署

## 后台管理模型的具体操作（方案 A 落地后）

1. 在 New API 控制台添加/启用/停用模型
2. 官网模型广场通过接口自动同步
3. 无需改官网代码
